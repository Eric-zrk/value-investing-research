# 价值投资研究工具

面向个人研究者的本地财务分析工具，提供财报下载、财务自动评分、A股市场研究、股东回报倾向评分、一键研究和质量与安全边际分析。

本项目以可解释的财务指标辅助研究。评分不包含护城河、管理层诚信等人工判断；统一估值参数也不能替代行业和公司研究。程序不执行交易，筛选结果不构成买入建议。

## 安装与首次使用

当前启动脚本面向 Windows，安装脚本使用 Python 3.13。其他系统尚未验证。

1. 将完整源代码解压到同一文件夹，不要只复制单个启动文件，也不要在压缩包内运行。
2. 安装 Python 3.13，并确保 Windows 的 `py` 启动器可用。
3. 双击本文件夹里的 `setup.cmd`，联网创建 `.venv` 并根据 `requirements-lock.txt` 安装依赖。
4. 确认窗口显示环境配置完成；红色报错时应先处理错误，再运行模块。
5. 从 `start.cmd` 下载一家公司的财报，再运行 `analyze.cmd` 验证单家公司分析。确认正常后再做大批量任务。

首次全市场运行可能需要数小时乃至更长。不要把全市场抓取当作首次安装检查。

## 模块入口与建议顺序

| 入口 | 用途 | 前置条件 |
|---|---|---|
| `setup.cmd` | 安装或重建本机运行环境 | Python 3.13及网络 |
| `start.cmd` | 下载一家公司的利润表、资产负债表和现金流量表 | 网络；A股六位代码或港股五位代码 |
| `analyze.cmd` | 本地财务80分分析和可视化 | 已下载对应公司的财报 |
| `market.cmd` | A股市场快照、离线重算、候选或全市场财报批处理 | 首次获取需联网 |
| `return.cmd` | 一家公司股东回报100分分析 | 本地财报；首次获取分红需联网 |
| `oneclick.cmd` | 自动抓取适用公司资料，按股东回报规则筛前十并生成综合报告 | 网络、稳定硬盘连接和足够时间 |
| `safety.cmd` | 对已有一键研究数据进行质量与估值筛选 | 已有一键研究任务及财报；刷新报价需联网 |

建议顺序：安装 → 单家公司下载和财务评分 → 股东回报分析 → 一键研究 → 质量与安全边际分析。

港股目前提供财报下载和带口径确认要求的财务分析；A股全市场、股东回报和一键筛选流程不能直接视为港股适配功能。

## 数据与文件管理

所有路径以当前项目文件夹为基准：

- `data`：本机下载的原始数据、来源记录、缓存和任务指针；运行后生成。
- `分析结果`：各模块的报告、评分明细和任务状态；运行后生成。
- `.venv`：当前电脑创建的Python环境；不随源代码发布。
- `*_config.json`：各模块参数。修改后保留版本记录，避免把不同规则的结果直接比较。
- `requirements-lock.txt`：依赖版本清单。

CSV与配套来源JSON一起保存。原始数据与可视化结果是不同文件，删除报告不会替代备份原始数据。运行中的任务状态不要手工删除。

项目放在移动硬盘时，下载和分析期间保持连接，结束后安全弹出。换电脑、移动目录或改变盘符后应重新运行 `setup.cmd`；虚拟环境不是独立便携运行时。旧任务可能记录绝对路径，移动后应新建任务，不能保证原断点可继续。

公开仓库只应包含代码、参数、说明和经检查的示例；本机数据、日志、历史结果和运行环境由排除规则保留在本机，不需要为发布而删除。

## 财务评分与A股市场研究

### 财务评分：双击 analyze.cmd

仍读取 data\a_代码 或 hk_代码 的三张财报，生成Markdown、CSV、JSON、离线可视化报告。
v2不再依赖有息负债、非受限资金、租赁明细、利息费用、可比股数或每股调整信息；旧补充模板不再是A股基础评分的必要条件。

新版十项指标：

| 模块 | 指标 | 权重 |
|---|---|---:|
| 盈利稳定性 | 收入年复合增长率 | 8 |
| 盈利稳定性 | 归母净利润年复合增长率 | 8 |
| 盈利稳定性 | 五年归母盈利年数 | 8 |
| 利润含金量 | 五年累计CFO/累计合并净利润 | 14 |
| 利润含金量 | 五年CFO为正年数 | 8 |
| 资产负债安全性 | 三年资产负债率中位数 | 10 |
| 资本回报能力 | 五年ROA中位数 | 8 |
| 资本回报能力 | 五年归母ROE中位数 | 4 |
| 现金创造能力 | 五年FCF为正年数 | 8 |
| 现金创造能力 | 五年合并净利率中位数 | 4 |
| 合计 | | 80 |

ROA=合并净利润/平均总资产；ROE=归母净利润/平均归母权益，均需六个年末余额。FCF=CFO-购建长期资产现金支出。四个增长间隔对应五年数据。
资产负债率=总负债/总资产，不等于有息负债率，更不代表现金足够还债。低资产负债率可能使某些高效商业模式被低估，应按行业校准。
ROE可能因杠杆变高，净利润增长可能来自增发并购，v2不再衡量每股摊薄；其便利性是以减少这部分信息为代价。
未提供值、亏损起点增长率、非正权益等仍标为未评，不强行补零。权重与阈值见score_config.json，所有档位在可视化报告可展开。
不得把v1与v2分数直接排名比较。旧报告保留原版本和原权重，不重写历史结果。
银行、保险、证券、地产开发仍需专用模型。港股保留原长表转换和单位/币种确认要求，本次不是港股专项适配升级。

### A股市场研究：双击 market.cmd

1. 获取上市名单、沪深京A股行情和指定报告期业绩，生成全市场看板。
2. 重算已有快照：调整筛选阈值后可离线重算，也可关联最新本地财务评分。
3. 初筛候选财报批处理：默认每次10家，可设置数量或all。
4. 全市场一般企业财报批处理：排除已识别的金融/地产和行业未知者，按代码依次处理。此顺序不是推荐排名。

选项1默认业绩期为上年度1231；输入YYYYMMDD可换季末。单次批量接口包含很多页，各来源最长等待180秒，失败时会报告，已下载快照保留，不把残缺数据冒充完整抓取。
上市名单是一切覆盖率的基准；行情或指定期业绩缺失的股票仍保留，并说明原因。业绩源还可能含新三板、B股等，名单外代码不会混入A股研究表。
新上市股票可能没有指定年度业绩；停牌、数据源遗漏都可能导致缺行情，不自动认定退市。

### 市场数据与价值投资

市场数据有助于衡量价格、估值和成交条件，但不提供护城河或未来现金流的确定答案。
动态PE、PB、ROE、同比、成交额只作为可调整的初筛条件，不合成为“股票质量分”。涨幅和换手率不加到财务80分中。
默认条件：动态PE>0且≤25，PB>0且≤3，单快照成交额≥1000万元，指定期收入与利润同比≥0%，ROE≥8%，净利润为正。排除名称含ST/退、行业不适用或未知、价格无效等情况。阈值仅是研究起点，未经回测。
市场源为动态PE，不能称为TTM PE；季度ROE不年化；单快照成交额并非过去20日平均流动性。低PE可能来自周期顶部，高PE也不必然排除价值投资。
不符合条件的股票不会被删除；看板可搜索、筛选、排序并导出当前视图，完整数据另存CSV。
看板另列同行正PE/PB的横截面分位。行业内至少5个有效正值才计算，使用相同值的中位排名，越低只代表该倍数相对同行低，不代表内在价值更高或行业分类足够精细。同行数和分位也保存在CSV。

### 数据与结果位置

- data\a_market\抓取时间：三份原始CSV及来源时间、版本、报告期与SHA256记录。
- 分析结果\A股全市场\分析时间：全市场分析.csv、初筛候选.csv、分析数据.json、分析元数据.json、A股市场看板.html。
- data\a_代码：公司三大财报。
- 分析结果\a_代码\分析时间：五年财务分析结果。
- 分析结果\批量任务：逐家公司成功/失败记录，失败后可重试。

批处理复用已有完整三张财报，不自动更新旧报表。需要更新时先用下载模块重新下载；相同输入且已用v2评分的公司会跳过。报告覆盖不足仍会标未评，不能把“已分析”当作80分全部可评。
看板关联本地财务分时同时显示覆盖率、版本和年度。没下载五年财报的股票显示“未做本地分析”，不会用一年ROE冒充五年质量分。
历史快照按抓取时间保留，抓取时间不是交易所成交时间，非交易日可能是上一交易时段行情。业绩公告日期不等于历史可得数据，本程序未实现无未来信息/无幸存者偏差回测。

## 股东回报倾向评分

### 100分结构

- 五年分红覆盖20：每个已确认分红年度4分；五年都有分红20分。
- 分红稳定15：起始15分；每次正值间减配扣3分，正分红转零断供扣5分，最低0分；五年均零不得此分。持平不扣稳定分。
- 分红增长10：四个年度间隔，各2.5分；双方为正且增长才得分，持平不拿增长分，零转正不计增长分。
- 最近连续分红5：从最近一年往前数，连续每年1分。
- 五年持续盈利20：五年归母净利润每个正值年度4分。
- 利润逐年增长10：四个年度间隔，各2.5分；双方为正且增长才得分。
- 最近连续盈利5：从最近一年往前数，连续每年1分。
- 五年正经营现金流10：每年2分。
- 五年正自由现金流5：每年1分。FCF=经营现金流-总资本开支。

示例：分红[1,1.1,0,1.2,1.3]时，分红覆盖16、稳定10、增长5、最近连续2，总计33/50。五年分红[1,1,1,1,1]时，覆盖20、稳定15、增长0、最近连续5，总计40/50。
断供会在覆盖、稳定性和最近连续性几个维度影响得分，这是现金分配偏好，并非声称这些指标互相独立。

### 分红口径与未知规则

使用公开接口RPT_SHAREBONUS_DET原始字段，按除息自然年合并已实施事件。PRETAX_BONUS_RMB为每10股派息，除以10得到税前元/股；不将送转当成现金回报，不把预案当实施。除息日不是实际到账日，也不是利润所属年度。
同一报告期、同一除息日的重复事件去重，冲突暂停对应年度；年度与中期事件可相加。接口可能漏记特别分红，不承诺公司全部事件已覆盖，所以分红评分属于源内记录的观察分。
找不到记录不是未分红，标未知；五年含未知时对应指标暂不评、不重新放大权重。
若五年内检出送转，名义每股分红增长和减配指标暂停评分，避免股数变化造成误判。本模块不能保证识别所有拆并股。
特别分红可能使次年显得减配，界面会提醒；本版本不自动识别和剔除特别分红。

若有公告确认某自然年无现金分红，可以在原始JSON副本中填写 verified_annual，例如 {"2023":0}，并填写 verification_source 的公告来源；--dividend-file 可离线读取该副本。未确认不要填零。

### 文件与参数

权重在return_config.json可调整，必须为正且合计100。
原始分红文件保存data\dividends\代码，输出在分析结果\股东回报\代码\分析时间，包含可视化页面、评分明细CSV和完整JSON。
界面分别显示已得分/100、覆盖权重、未知部分和逐项扣分过程。原80分与本100分不可直接相加。
默认使用前五个已结束自然年；不是无未来信息的回测。本版仅A股，银行等行业的现金流不能与普通企业直接比较，需专用解释。

命令行：
```
.venv\Scripts\python.exe shareholder_return.py --symbol 600519 --open-report
.venv\Scripts\python.exe shareholder_return.py --symbol 600519 --dividend-file data\dividends\600519\某个原始文件.json
```

### 如何解读

它评估的是持续现金分配倾向，不是完整企业好坏。优秀再投资企业可能低分；高分不能排除借债分红、高估值、一次性收益或经营恶化。
不把分红率当作总收益率，未加入PE、PB、股价涨幅或高股息奖励。未来回报还取决于买入价格、盈利变化、分红税及再投资等。
权重和扣分规则为研究初始参数，未经回测。

## 一键研究

### 执行顺序

1. 获取或复用7天内、上一年度1231报告期的市场分析名单；建立固定快照，保证一个任务内不会随时改变名单。
2. 排除行业未知和当前通用模型不适用的金融、地产企业；不使用原PE/PB初筛条件预先删除其他公司。
3. 对全部适用公司获取三大财报和历史分红，计算股东回报100分。该分数含盈利和现金流，必须在排名之前获取财报，无法只下载前十公司的财报。
4. 数据覆盖100/100的记录参与排名，取前10；不足10不凑数。未知、失败或送转导致不可比者单列。
5. 对前十生成财务80分与可视化报告，并合并原市场快照到每家公司的一页综合报告。
6. 自动打开总览，点击公司可查看三个模块的信息。两个分数不相加，估值不会改变股东回报排序。

同分按分红子分、再按代码排序。排序表示当前规则下的持续现金分配偏好，不是内在价值前十，也不是未来回报最高的十家公司。
市场模块目前是估值/风险分析，不提供独立总分；综合页面展示它的所有字段、筛选原因和风险。行业限制、未知分红与特别分红漏记等原模型限制继续适用。

### 时间与续跑

首次全市场可能需要数小时乃至更长，需要联网并保持硬盘连接。每家公司最多3张财报及分红请求，程序串行并保留间隔，不采用大量并发。
任务位置为 分析结果\一键研究\任务时间，每家有执行日志，states保存可恢复状态，任务摘要.json记录已完成/失败/未评数量。原始数据仍在data目录。
默认复用30天内、年度齐全的财报和分红缓存；它不是实时数据。原始JSON的分页完整也不等于分红源绝对无漏项。
关闭窗口会保留已完成公司。再次双击自动继续相同配置的任务，跳过输入未变且已成功的公司；失败者重新尝试。输入数据或评分规则变化时不会复用旧评分。
如旧任务已完成，再次打开会复用结果并重建前十的财务报告；希望新建市场名单任务可使用 --new。--new主要刷新市场名单，仍会按缓存天数复用财报和分红。

### 总览与报告

总览显示市场名单数、完整可比数、失败数、排除数及暂列前十。存在失败/未处理时明确标“尚未完整成功”，不会把部分样本冒充全市场结果。
即使本轮全部完成，前十仍只代表适用通用模型且数据完整的公司；金融/地产与缺资料公司没有被证明比前十差。
每家公司页面包含股东回报逐项得分、权重、扣分、五年数据；财务80分全部细则；完整市场字段及口径。
总览和公司页面可以离线打开；嵌入页面自包含。原始路径仍指向项目数据，移动项目后需重建环境并新建任务。

## 质量与安全边际分析

### 默认规则

质量分完整覆盖80分且≥64；TTM归母、扣非归母、合并利润均正；扣非/归母≥80%；最新同比≥-10%；最近资产负债率≤50%；归母权益为正；TTM CFO≥合并净利润；TTM和三年CFO减总资本开支均正。负TTM资本开支作为数据口径异常，暂停筛选。原任务行业排除和名称ST/退等风险保留。
正常化盈利=min(TTM归母、TTM扣非归母、最近三年归母利润中位数)。原股东回报是否完整不成为进入本模块的必要条件；它是辅助信息，不与财务分相加。
五年股利+退出价值贴现：保守为增长0%、分配50%、退出PE8、要求回报12%；基准3%、60%、12、10%；乐观5%、65%、15、10%。股价≤基准价值70%才通过默认价格规则。配置require_below_conservative=true可增加必须同时低于保守价值的限制。
这些是统一研究假设，不是行业公允估值。治理、护城河、收费权期限、完整债务、再投资回报与周期风险仍须核查，最终通过不等于建议买入。

### 参数与运行

safety_config.json控制质量门槛、折让要求、三情景参数、报价可接受天数。必须用小数填写百分比，如0.30是30%。不建议只为产生名单而提高增长率或PE。
报告期默认为按当前日期推定的已过披露期限季度：5—8月一季报、9—10月半年报、11—12月三季报、1—4月上一年三季报（不自动选择尚未普遍披露的年报）。它不保证所有公司已经披露，缺值会标记。旧年份研究请明确传 --period。
本模块只读取已有本地财报，不自动补下载。缺季度、缺报表、币种冲突或重复冲突会报告，不当零，不重分配权重。前五个年度与三年历史根据报告期自动移动；年报口径TTM直接使用全年，不重复累加。
首次计算可能需要几分钟，后续数据和原评分配置未变时会复用单家公司缓存；改变本模块质量阈值仍会重新判断。输入文件变化会使缓存失效。--refresh-financial强制重算。缓存位于data\safety_cache，不移动原始数据。

### 结果

分析结果\质量与安全边际\运行时间，保存全部公司CSV、通过价格规则CSV、质量通过观察表CSV、筛选结果JSON、原始报价JSON和筛选看板HTML。
看板显示总覆盖、错误、质量通过数、价格通过数；所有未通过原因保留。可点击公司展开财务指标、估值输入及来源文件哈希；可切换仅显示价格通过者。若结果为零，不自动放宽参数或凑十家。
报价时间来自数据源，页面保留UTC+08:00原始时间口径；不是实时成交保证。默认只接受7天内报价，报价缺失、停牌无价或过期时不作价格通过判断。行情总市值隐含股数、A/B/H股与送转口径仍需人工核实。
本模块不修改旧一键研究任务或替换评分算法，不能把观察线理解为跌到就买，也不把全市场初筛当成完成尽调。

## 财务评分可视化

日常仍运行 analyze.cmd，分析完成后会用默认浏览器打开“可视化评分报告.html”。如浏览器未打开，请进入“分析结果\市场_代码\分析时间”双击此文件。
页面是自包含离线文件，无需网络或注册账户，可以复制发送或打印保存PDF。

页面依次提供：

1. 已取得分数/80、覆盖率、未评权重、未知部分对应的可能总分区间。
2. 五个模块的满分、实际得分、所占权重及进度条。
3. 十项指标表：权重（分和百分比）、原始指标值、0～5等级、得分/满分、缺失原因。
4. 点击“评分细则”中的任一项，展开计算公式、本次得分算式和全部六档阈值。当前命中档位会高亮。
5. 年度输入数据、模型限制及输入文件校验记录。

进度条三段分别表示“已取得”“已评但未取得”“未知未评”。未评指标不是0分，也不会重新放大其他权重。
例如40.70分、覆盖47/80，表示在可评的47分中取得40.70分，另有33分未知；不能当作完整企业评分40.70分。
所有指标沿用原评分配置，不包含新增主观分数。不同公司数据覆盖率不同时，不宜只按已取得总分排序。
“打印/保存为PDF”会自动展开所有细则，然后打开浏览器打印窗口。

报告中收入和利润金额沿用原始数据单位，不自动换算成人民币亿元。增长率显示为百分数，其他指标按次数或倍数显示。
完整计算结果、补充财务数据和配置快照仍保存在同目录的评分结果.json。

## 常见问题

### 双击启动文件后闪退怎么办？

确认已完整解压，启动文件与程序位于同一文件夹，并已成功运行 `setup.cmd`。在文件夹内打开终端运行对应启动文件可保留报错信息。不要从旧安装包、历史备份或压缩包中启动。

### 提示找不到 akshare 怎么办？

重新运行当前项目的 `setup.cmd`。安装到系统Python的依赖不一定存在于本项目的 `.venv` 中。

### 屏幕可以熄灭吗？

显示器熄灭通常不影响任务，但电脑睡眠、休眠、关机或硬盘断开会中断执行。长任务期间应保持电脑唤醒；合盖行为取决于系统电源设置。关闭窗口后可按一键研究的续跑规则重新启动。

### 完整可比是否代表所有财务资料都完整？

不代表。它只表示对应模型规定的指标已具备可评分输入；不同模块有不同完整性要求，不代表完整尽调、原始数据绝无遗漏或公司没有风险。

### 为什么取得分数低，或者没有筛出公司？

先检查未评权重、数据年度、模型版本和失败原因。缺失值不会按零补齐，也不重新放大其他权重；不能只按不完整总分排序。安全边际筛选结果可以为零，程序不为凑名单自动放宽门槛。

### 能否把80分和100分相加？

不建议。两套规则含有重叠的盈利和现金流指标，评价目的也不同。估值是另一维度，应结合模型假设单独阅读。

## 缺失数据与候选资格

各模块的完整性要求不同：财务分析保留已核验的部分评分，并展示未评原因；市场初筛缺少必要筛选字段时不进入候选。一键研究仅要求股东回报评分完整覆盖100分才能参与该项排名，后续财务80分不完整、或部分市场字段缺失，不会自动移出股东回报前十；相关状态在综合报告展示。质量与安全边际模块另行要求财务80分完整及必要近期数据齐全，缺报价或报价过期不能通过价格筛选。

因此，当前版本并未实现“所有模块任一字段缺失，统一排除公司”的规则。完整可比仅指相应模型所需数据可评分，不保证数据源无遗漏。
